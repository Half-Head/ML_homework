## 1. Разведочный анализ и чистка

`hw1_train.jsonl` — 10 000 диалогов пользователей. Размечено 3 000 диалогов (`reaction`, `task_type`).

Формат: одна строка = один диалог, у каждого `dialog_id`, `language`, `n_user_turns`, `turns` (список реплик `{role, text}`), `labels` (может отсутствовать).

### Структура и пропуски

- `n_user_turns` совпадает с реальным числом user-реплик для всех 10 000 диалогов.
- Число реплик user всегда равно числу реплик assistant.
- Пропуски только в `labels`: размечено 3 000 из 10 000.

**Решение.** Диалоги без меток не используем для reactions, используем для themes.

## 3. Задача 1. Реакция пользователя

### Метрики

**Основная метрика — macro-F1.** Учитывает все три класса одинаково, устойчива к дисбалансу. Дополнительно:
- **balanced accuracy** — средняя точность по классам.
- **accuracy** — для сравнения с baseline.
- **precision/recall/F1 по классам** — видеть, какой класс проседает.
- **confusion matrix** — понять, куда уходят ошибки.

**Почему не accuracy.** При дисбалансе 59/31/10 модель, всегда предсказывающая `neutral`, даёт accuracy 0.59, но macro-F1 всего 0.25. Accuracy вводит в заблуждение.

### Схема разбиения

Разбиение 65 % train / 15 % val / 20 % test с учётом групп почти-дубликатов:

**Кросс-валидация.** `GroupKFold(n_splits=5)` на train с группами почти-дубликатов. Гиперпараметры выбираются по среднему macro-F1 по фолдам. TF-IDF обучается **внутри каждого фолда** через `Pipeline` — это исключает утечку.

### Своя модель

**Гипотеза.** Основная информация о реакции содержится в последних репликах пользователя.

**Проверка гипотезы.** Обучили LogReg на разных вариантах текста:

| Вариант | macro-F1 | F1_positive | F1_negative |
|---------|----------|-------------|-------------|
| **last_two** | **0.599** | **0.506** | **0.551** |
| last_three | 0.591 | 0.495 | 0.541 |
| all | 0.555 | 0.411 | 0.524 |
| last | 0.533 | 0.417 | 0.474 |
| first | 0.488 | 0.277 | 0.507 |

`last_two` обгоняет `all` — гипотеза подтверждена.

**Реализация.** Обучаем две LogReg:
1. `p_full` — вероятности на полном диалоге пользователя.
2. `p_last2` — вероятности только на последних двух репликах пользователя.

Итоговая вероятность: `p = W · p_last2 + (1 - W) · p_full`. Вес `W` подобран через 5-fold CV.

**Подбор W через CV:**

|---|---------------------------|
| **0.8** | **0.5547 ± 0.0311** |
| 0.9 | 0.5533 ± 0.0272 |
| 0.7 | 0.5526 ± 0.0272 |
| 1.0 (только last2) | 0.5518 ± 0.0303 |
| 0.6 | 0.5505 ± 0.0325 |
| 0.5 | 0.5457 ± 0.0285 |
| 0.4 | 0.5289 ± 0.0261 |
| 0.3 | 0.5150 ± 0.0280 |

**Итог:** W=0.8 лучше W=0 и W=1 внутри этого эксперимента.

Основные ошибки: neutral ↔ negative.

Пример 1. neutral → negative: длинный технический диалог с ложными маркерами

Пользователь задаёт последовательные задачи, никакого недовольства нет. Модель поставила negative.
Почему ошибка. Диалог длинный, много терминов `no`, `not`, `without`, `cannot` в математическом контексте.\

Пример 2. neutral → negative: путаница в терминах

Пользователь изучает фреймворк и переспрашивает: «i got confused so wont those be models?», «what do you mean like relationships», «okay so what are controllers for». Нейтральное обучение, но модель поставила negative.

Пример 3. negative → neutral: повтор требования как сигнал раздражения

Пользователь проходит quiz. Ассистент даёт развёрнутые ответы, пользователь просит коротко — три раза подряд.
Почему ошибка. Реплики короткие и формально вежливые. Но повтор одной и той же просьбы — сигнал раздражения. Модель не учитывает повтор между репликами, только лексику внутри.

Пример 4. negative → neutral: ассистент извиняется за ошибку

Диалог про физику. Пользователь указывает: «You can get closer to the speaker and still be at a point of perfectly destructive interference». Ассистент признаёт ошибку: "My previous response did not consider all the possible points for destructive interference, and I apologize for that mistake". Тут неоднозначно, негативная это реакция или нейтральная.
